# Bird Species Observation Analysis — Streamlit App

Interactive dashboard analyzing bird species distribution and diversity across
**Forest** and **Grassland** habitats, built from NPS bird-monitoring point-count
data covering 11 administrative units (ANTI, CATO, CHOH, GWMP, HAFE, MANA, MONO,
NACE, PRWI, ROCR, WOTR).

The app covers every analysis area called out in the project brief: temporal
trends (season/month/time-of-day), spatial patterns (admin unit map, plot-level),
species diversity (richness, sex ratio, ID method), environmental correlations
(temperature, humidity, sky, wind, disturbance), distance & flyover behavior,
observer trends, and conservation insights (PIF Watchlist, Regional Stewardship,
AOU codes).

```
│   ├── Bird_Monitoring_Data_GRASSLAND.XLSX   # raw source (11 sheets, one per admin unit)
│   └── cleaned_bird_data.csv                 # generated by data_prep.py
├── bird_monitoring.db                        # generated SQLite DB (used by the app)
├── data_prep.py                              # cleaning / preprocessing / ETL script
├── app.py                                    # Streamlit dashboard
├── requirements.txt
└── README.md
```

## What `data_prep.py` does (Data Cleaning & Preprocessing)

1. Loads **all 11 sheets** from both workbooks (one sheet per admin unit) and
   tags each row with its `Habitat` (Forest/Grassland) and source sheet.
2. **Reconciles schema differences** between the two habitats:
   - Forest's `NPSTaxonCode` and Grassland's `TaxonCode` are unified into one
     `Taxon_Code` column.
   - Forest's `Site_Name` (absent in Grassland) and Grassland's `Previously_Obs`
     (absent in Forest) are added to the other habitat as nulls so both sets
     share one schema.
3. **Cleans** the data: trims whitespace, drops exact duplicate rows
   (~1,700 found — common in this type of point-count data), standardizes
   boolean columns (`Flyover_Observed`, `PIF_Watchlist_Status`,
   `Regional_Stewardship_Status`, `Previously_Obs`, `Initial_Three_Min_Cnt`),
   fills missing `Sex` with `"Undetermined"` and missing `Distance` with
   `"Not Recorded"`, and coerces numeric/date/time columns.
4. **Engineers features** used throughout the dashboard: `Month_Name`,
   `Month_Num`, `Season`, `Day_Of_Week`, `Start_Hour`, and
   `Observation_Duration_Min` (from `Start_Time`/`End_Time`).
5. Writes the cleaned flat file to `data/cleaned_bird_data.csv` **and** loads it
   into a SQLite database (`bird_monitoring.db`), table `bird_observations`,
   plus a small `admin_unit_locations` lookup table (approximate park
   centroids, used only for the overview map — the source data has no
   plot-level GPS).

Result: **15,372 cleaned observations**, 126 unique species, across 2 habitats
and 11 admin units.

You only need to re-run `data_prep.py` if you replace the source Excel files;
the Streamlit app reads the generated database/CSV, not the raw workbooks, so
the dashboard loads quickly.

## Run it locally

1. **Install Python 3.10+** if you don't already have it.
2. Open a terminal in the `bird_species_project` folder and create a virtual
   environment (recommended):
   ```bash
   python -m venv venv
   source venv/bin/activate        # Windows: venv\Scripts\activate
   ```
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Generate the cleaned dataset and database (only needed once, or whenever
   the source Excel files change — `bird_monitoring.db` is already included,
   so you can skip this step if you just want to run the app):
   ```bash
   python data_prep.py
   ```
5. Launch the app:
   ```bash
   streamlit run app.py
   ```
6. Streamlit will open the dashboard in your browser at
   `http://localhost:8501`.

## Deploy it to Streamlit Community Cloud (free hosting)

Streamlit Community Cloud deploys directly from a GitHub repository, so the
first step is getting this project onto GitHub.

### 1. Push the project to GitHub

1. Create a new **public** (or private, if you're on a paid plan) repository
   on GitHub, e.g. `bird-species-observation-analysis`. Don't initialize it
   with a README (you already have one).
2. From inside the `bird_species_project` folder:
   ```bash
   git init
   git add .
   git commit -m "Bird species observation analysis - Streamlit app"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```
   Make sure `bird_monitoring.db` and `data/cleaned_bird_data.csv` are
   committed too (the app reads them directly at startup) — the whole
   project is about 14 MB, well within GitHub's limits, so no Git LFS is
   needed.

### 2. Deploy on Streamlit Community Cloud

1. Go to **[share.streamlit.io](https://share.streamlit.io)** and sign in
   with your GitHub account (create a free account if you don't have one).
2. Click **"Create app"** → **"Deploy a public app from GitHub"**.
3. Fill in:
   - **Repository**: `<your-username>/<your-repo>`
   - **Branch**: `main`
   - **Main file path**: `app.py`
4. (Optional) Click **"Advanced settings"** to pin a specific Python version
   (3.11 is a safe choice) if you want to match your local environment
   exactly.
5. Click **"Deploy"**. Streamlit Cloud will install everything from
   `requirements.txt` and launch the app — the first deploy typically takes
   1–3 minutes.
6. Once live, you'll get a shareable URL like
   `https://<your-app-name>.streamlit.app`. Any future `git push` to `main`
   automatically redeploys the app.

### 3. Updating the app later

Just edit your files locally, then:
```bash
git add .
git commit -m "Describe your change"
git push
```
Streamlit Cloud picks up the push and redeploys automatically (usually within
a minute). If you change the raw Excel files, re-run `python data_prep.py`
locally first and commit the refreshed `bird_monitoring.db` /
`cleaned_bird_data.csv` — the cloud app does not re-run the ETL step itself.

## Notes & assumptions

- All observations in the source data fall within **2018** — the app still
  includes a Year filter so it keeps working unchanged if you extend the
  dataset with more years later.
- The map on the **Spatial** tab plots each administrative unit at its
  approximate park centroid (public, well-known NPS locations), not exact
  survey-plot GPS coordinates, since the source data doesn't include
  plot-level latitude/longitude. This is called out in the app itself.
- "Watchlist" refers to the Partners in Flight (PIF) Watchlist status column;
  "Stewardship" refers to Regional Stewardship Status.
